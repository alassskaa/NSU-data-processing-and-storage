# Асинхронный обход ресурсов HTTP-сервера

Паук обходит сервер из `Task_J3-server.jar`, начиная с `/` и переходя по
`successors`, и выводит все `message` в лексикографическом порядке.
Требуется Java 21.

## Запуск

```bash
java -jar Task_J3-server.jar ИмяФамилия
./gradlew run -q --console=plain --args="8080"
```

Порт необязателен, по умолчанию 8080. Тесты: `./gradlew test`.

## Устройство

- `Spider.visit(path)` запрашивает страницу и запускает каждого нового
  потомка в своём виртуальном потоке (`newVirtualThreadPerTaskExecutor`).
  `close()` executor'а ждёт всё поддерево, поэтому возврат из `visit("/")`
  означает конец обхода.
- Посещённые пути — `ConcurrentHashMap.newKeySet()`, каждый путь
  запрашивается один раз.
- Таймаут запроса 30 с, при ошибке до трёх попыток.

## Результат

Граф сервера — 100 цепочек по 10 вершин с задержкой ответа до 12 с. Обход по
уровням занял бы 10 · 12 = 120 с, а без ожидания уровней время равно самой
длинной цепочке: собрано 1001 сообщение за ~90 с.
